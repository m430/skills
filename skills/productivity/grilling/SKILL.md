---

毫不松口地拷问用户，直到达成共同理解。把它映射成一棵**设计树（design tree）**：每个决策都会分出挂在它下面的决策。

**前沿（frontier）**是所有前置条件已经敲定的决策：也就是你_现在_就能问、不必猜测尚未听到的答案的问题。

## 怎么问

运行环境提供结构化提问工具（`AskUserQuestion`，Qoder 与 Claude Code 均有）时，用它提问，**一次只问一个问题**：

- 一次工具调用只放一个问题，从当前前沿里挑**最优先**的那个。然后停下，等用户回答，再重新计算前沿，问下一个。
- 选项就是候选答案，2 到 4 个；多个答案可以同时成立时允许多选。把推荐答案放在第一位，标签结尾标注“（推荐）”。问题再开放也要给出候选答案：用户永远可以选“其他”自由作答。
- 标签只写答案本身，保持简短；背景与权衡放进问题正文和选项描述。给问题起一个很短的标题（12 字符以内）。

用户每答一题，这棵树就重塑一次：已敲定的决策把前沿向外推，并解除依赖它们的问题的阻塞。一个答案依赖仍未关闭问题的，属于_更晚_的位置，不属于现在。

工具不可用时退回文本格式：**一轮之内问完整条前沿**，给每个问题编号、附上推荐答案，然后等待回答。一轮按如下格式呈现：

```
❓ **Q1** - **<question title>**: <question body, might be multiple paragraphs, including multiple choices>

➡️ <your recommended answer>

---

❓ **Q2** - **<question title>**: <question body, might be multiple paragraphs, including multiple choices>

➡️ <your recommended answer>
```

查明_事实_是你的职责，从来不是用户的。当前沿问题需要环境（文件系统、工具等）中的事实时，派一个子代理去查明；凡是能自己查到的，就不要问用户。不要因此阻塞：一个运行中的探索是一个未敲定的前置条件，所以只有位于它下游的问题等待子代理回报，其余前沿问题现在就问。_决策_是用户的：逐项提给用户，然后等待。

当前沿为空时，会话结束：设计树的每条分支都走到了，没有任何东西被悄悄假设。在用户确认你们已达成共同理解之前，不要据此采取行动。

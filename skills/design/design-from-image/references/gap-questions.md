# 缺口提问库

图答不了的决策。**最多挑 5 个，一次问一个**，选项即候选答案、推荐项放首位（运行环境有 `AskUserQuestion` 就用它，没有就退回文本）。

底座答得了的**不要问**。换了 shadcn 底座之后，这个清单比从零做设计系统短得多：

- 图上没有的控件：继承底座，不问。
- hover / focus / active / disabled / 错误态：组件默认就是答案，只有图上专门画了不一样的才需要记，记成 `观察到`。
- 字阶、间距、阴影的刻度：Tailwind 现成的，不问。
- 图标形状：沿用现有图标库，不问。

图上已经画了的也不要问。纯静态页跳过动效；图里明确画了暗色模式就跳过暗色。别照着清单念。

## 挑问题的优先级

1. **不答就没法写 design.md 的**：图上字体与现状不一致时的取舍、尺寸对不上底座档位时怎么办。
2. **不答会导致实现时各写各的**：暗色模式、响应式。
3. **锦上添花的**：动效、语义色。项目小就直接跳过。

## 问题

### 字体

图上认出的字体是 [疑似 X]，仓库现在用的 `--font-sans` 是 [Y]。

- 沿用仓库现状（推荐）
- 换成图上的字体，授权我来确认
- 用近似的免费字体替代

认不准图上字体时，直接说认不准，别给一个像模像样的名字让用户以为提取出来了。商业字体不要擅自下载，也不要写进 design.md 当作已授权。

### 尺寸与档位对不上

图上量到 [控件] 的高度是 [N]px，底座的尺寸档是 [h-9 36px / h-10 40px 之类]，对不上。

- 落到最近的档位（推荐）：差 2px 以内按量误差处理，实现简单，也不破坏组件的一致性
- 照图上尺寸改组件默认：这是有意的设计选择，改了要在组件文件里落地
- 我说明真正想要的

这一问的答案通常能推广到同类控件，别每个控件问一遍。

### 暗色模式

- `.dark` 保持仓库现状不动（推荐）
- 按改后的亮色令牌推导一套
- 我提供暗色参考图

第一项是默认答案：改动只落在亮色，暗色留到有人真的用它的时候再说。第二项在项目确实要做暗色、又暂时没有参考图时选，推导出来的值标 `推断`。第三项最准，暗色的值照常走采样。

### 响应式

- 只做单一尺寸，写死（推荐给工具类、内部页）
- 需要断点，我指定
- 按内容驱动，不设断点

选了要断点就追问：最小支持宽度是多少？

### 动效

- 不做动效（推荐）
- 极简：定一个时长加一个缓动，全站复用
- 我提供动效参考

底座只有过渡的约定，没有成套的动效规范，所以这一问的答案要么是「不做」，要么是自己定一小套。

### 语义色

图上没有破坏性操作的样式。

- `--destructive` 保持仓库现状（推荐）
- 按图上的主色系推导
- 我给具体色值

选了推导才追问：危险色是保持品牌色相，还是用通用红？（推荐通用红，错误提示不该看起来像品牌宣传）

### 槽位归属有歧义

图上[某个面 / 某个灰]既像 [`--muted`] 又像 [`--card`]，两种填法会让后面的 UI 长得不一样。

- 按 [推荐的那种] 填（推荐）
- 按另一种
- 两个都不对，我说说它到底是什么

只在真的分不清时问。分得清就自己定，别拿这种问题占用提问配额。

## 问完之后

- 用户答了：记 `裁定`，写进 design.md 对应章节。
- **图上没画、底座现状能答的：记 `继承`**，一句话带过，不要展开描述。
- 图上没画、用户也没答，底座现状也不是答案的：能按惯例推的记 `推断` 并写明依据，推不出来的进「缺口」章节。
- 用户改口推翻之前的答复：改 design.md，别留两个说法。

# 提取方法

每类令牌怎么从一张图里读出来，读不准时怎么标。目标始终是填 shadcn 的槽位，不是从头发明一套令牌。

## 输入类型

| 类型 | 特征 | 处理 |
|---|---|---|
| 控件展示板 | 多个控件平铺排列，背景干净 | 最理想，逐个控件提取 |
| App 截图 | 完整手机屏，含状态栏与导航 | 忽略状态栏与页面背景，只取控件 |
| 网页截图 | 含浏览器外框或整页长图 | 先切出控件区域；长图按模块分区 |
| 设计稿导出 | 带标注线、红框、多画板 | 分画板提取，忽略标注层 |
| 拍屏 | 摩尔纹、透视变形、反光 | 颜色只作参考，明确告诉用户这张图的精度不可靠，建议换原图 |

参考图不必来自同类产品。App 截图提出来的配色与密度，一样能落到网页项目的槽位里，只是别把手机上的布局规律当成目标项目的布局。

图里没有 UI 控件（只有 logo、插画、照片）就停下，告诉用户这张图提不出设计系统。

## 颜色

按角色取，不按在图上出现的顺序取，取完直接填 [shadcn-base.md](./shadcn-base.md) 里的槽位。

1. **页面底**：`--background`。暗色参考图反着来。
2. **面**：卡片 `--card`、弹层 `--popover`、弱化面 `--muted`、悬浮与选中底 `--accent`。图上有几个面就填几个，多出来的不要硬塞进槽位。
3. **文字**：以 `--foreground` 与 `--muted-foreground` 两档为主；卡片里的文字才动 `--card-foreground`。
4. **交互**：主按钮 `--primary`，次按钮 `--secondary`。主操作与次操作要分开。
5. **语义**：`--destructive`。图里没有就**不要编**，留给缺口提问。
6. **边框与分隔线**：`--border` 与输入框的 `--input`。常常很淡，用 `scan` 以 `--tolerance 3` 扫。半透明的记下透明度估计。
7. **图表与侧栏**：图上画了 `--chart-*` 或侧栏才取。

取色纪律：

- 用 `sample` 或 `palette`，不要目测。同色系的两个点拿不准是不是一个色，`sample` 出来比 hex：通道差都在 2 以内按一个色处理，差得多就是两个色。
- **值直接抄脚本输出的 oklch**，不要手工换算，也不要换算成 hex 再往 CSS 里写。脚本的输出与 shadcn 的写法是同一个格式。
- 采样点落在纯色区域中心，离边框至少 2px，避开文字抗锯齿与阴影渐变。
- `--avg 3` 能压制 JPEG 噪点，但**跨在边缘上的点不能用它**，均值会把背景色掺进来。边缘附近一律单像素取样。
- 同一颜色在多个控件出现时记下全部出处，填槽时用它判断这是真角色还是偶然。

## 排版

1. **从大到小扫一遍**，把每段文字按视觉层级分组。
2. **字体族**：认得出来就写具体名字，认不出写「疑似 X 或同类几何无衬线」，并给置信度（高 / 中 / 低）。这一步是为了判断 `--font-sans` 要不要换、换成什么。
3. **字号**：以正文为锚，估出每级的像素值，再落到最近的 Tailwind 档位（`text-sm` 14px、`text-base` 16px、`text-lg` 18px、`text-xl` 20px、`text-2xl` 24px，完整刻度见 [shadcn-base.md](./shadcn-base.md)）。正好落在两档之间就照实写出来，别硬选一个装确定。
4. **字重**：记下出现的不同字重，落到 `font-normal` / `font-medium` / `font-semibold` / `font-bold`。
5. **行高**：正文与标题分别估，落到 `leading-*` 的档位。
6. **字距**：注意标题是否收紧、标签是否放宽，对应 `tracking-tight` / `tracking-wide`。

换算实际字号：如果知道图的真实渲染宽度（App 截图通常是 390pt 或 393pt 宽），用 `scan` 扫出文字块高度的像素数，按 `实际字号 = 像素高度 / 图宽 * 真实宽` 换算。换算过的值比 `~` 估算可信，标注成「观察到（按图宽 N 换算）」。

## 间距与尺寸

1. **先对照基准单位**：底座的间距基准是 4px（Tailwind 的 `--spacing`）。图上量到的最小重复间距贴不贴这个基准，决定了这套设计是顺着底座，还是另有一套节奏。
2. **再量四级**：控件内部（按钮、卡片、输入框、列表行的内边距）、同级元素之间（按钮组、表单字段、列表项）、区块之间、页面边距。
3. **量法**：用 `scan` 沿垂直或水平线扫过一段，读各分段的像素长度。
4. **落档位**：量到的像素落到最近的 Tailwind 档（`p-1` 4px、`p-2` 8px、`p-3` 12px、`p-4` 16px、`p-6` 24px、`p-8` 32px）。**明显不在刻度上、或者离两档一样近的，照实写出来**：那是这套设计的特征，不是量误差。
5. 不要往 `design.md` 里写裸像素。

## 形状与深度

- **圆角**：用 `scan` 斜着扫过角部，读过渡段的像素长度估半径；也可用 `sample` 逐点比对边缘。量出来的是基准半径，只定 `--radius` 一个值，`--radius-sm` 这些派生档位由底座算，不要单独写。出现两种明显不同的圆角时（比如卡片 8px、胶囊全圆），说清哪类控件用哪种；胶囊类的通常是组件里写 `rounded-full`，与 `--radius` 无关。
- **阴影**：记方向、模糊量级、是否带颜色，落到 Tailwind 的档位（`shadow-xs` 到 `shadow-2xl`）。阴影色常是主色的暗化版，或黑色低透明度。
- **边框**：宽度、颜色、是否只出现在某几条边，落到 `--border` 与 `--input` 两个槽位。

## 控件

对 Step 2 清点到的每个控件：

1. **先读仓库里对应的组件文件**（`components/ui/` 下），记下它现在长什么样：有哪些变体与尺寸档、默认用哪档圆角与阴影。这一步不能省，项目可能早就改过 shadcn 的默认。
2. 再记参考图里的控件：结构、高度、内边距、元素间距、颜色与字体的用法、圆角、阴影、边框。
3. **写差异**：与组件现状对得上的不写；对不上的写清差在哪（换尺寸档、换变体、改默认类）。

图里通常只画了默认态。hover、focus、active、disabled、loading、错误态不在图里，但**底座有**：底座默认能答的标 `继承`，答不了的（比如图上专门画了 hover 用主色描边）留给缺口提问。

图里没有的控件**不补**，也不用写进缺口章节。它们继承底座，用到时再说。

## 边界情况

- **图有透视或压缩变形**：只提取相对关系，标注绝对像素不可信。
- **分辨率太低**（控件小于 40px）：字号与间距标为估算，颜色仍然可信。
- **多画板设计稿**：按画板分别提取再归纳；画板之间冲突时问用户以哪个为准。
- **暗色模式图**：颜色角色反转（最浅的是背景而不是前景），语义色通常要调亮，标注这是暗色下的值，并说明 `.dark` 块是照它改还是沿用现状。
- **图是深色底上的浅色控件**：别把浅色当背景处理，先判断哪一层是页面底。

## 附录 A：填写时的命名纪律

- 槽位名照抄 [shadcn-base.md](./shadcn-base.md)，不要另造同义词，也不要发明 `--color-primary` 这类平行体系。
- 确实要新增令牌（图上有一个现成槽位放不下的角色），才同时写进 `:root`、`.dark` 与 `@theme inline` 三处，并在令牌表里说明为什么复用不了现有槽位。
- 别抄 shadcn 的出厂默认值。`--background` 的原值是什么不重要，**仓库现在是什么**才重要，后者从样式文件里读。
- 不写裸像素：间距落 Tailwind 档位，圆角只写 `--radius`，阴影用档位名。

## 附录 B：最常见的四个错误

1. **把 `design.md` 写成底座说明书**。shadcn 的槽位表、Tailwind 的字阶表在官方文档里，这里只记这个项目改了什么。抄一遍既占篇幅，又会在底座更新后变成错的。
2. **图里读到的每个颜色都塞一个槽位**。槽位是有限的语义角色，图上多出来的那几种灰多半该并进 `--muted` 或 `--accent`。
3. **图上没画的状态写得像真的一样**。hover 的色值从哪来的？底座现状能答的标 `继承`，答不了的就要么问、要么进缺口。
4. **只列了令牌，没写怎么用**。`--primary` 是 `oklch(...)` 没有用，「一个屏幕只有一个主操作，用它」才有用。
